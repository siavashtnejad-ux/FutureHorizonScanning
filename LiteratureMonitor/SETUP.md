# راه‌اندازی ماژول ۱ — فرم ثبت سیگنال

## ۱. ساخت Google Sheet
یک Google Sheet جدید بسازید (نام دلخواه، مثلاً «Ethical Horizon Signals»).

## ۲. افزودن Apps Script
- در شیت: Extensions → Apps Script
- محتوای فایل `apps-script.gs` را کپی و جایگزین کد پیش‌فرض کنید
- ذخیره کنید (Ctrl+S)

## ۳. Deploy کردن Web App
- Deploy → New deployment
- Type: **Web app**
- Execute as: **Me**
- Who has access: **Anyone**
- Deploy را بزنید و مجوزهای لازم را تأیید کنید
- آدرس URL که نمایش داده می‌شود را کپی کنید (چیزی شبیه `https://script.google.com/macros/s/.../exec`)

## ۴. اتصال فرم
فایل `signal-intake.html` را باز کنید، خط زیر را در انتهای فایل (تگ `<script>`) پیدا کنید:

```js
const ENDPOINT_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE";
```

و آدرس مرحله ۳ را جایگزین کنید.

## ۵. تست
فایل HTML را در مرورگر باز کنید، یک سیگنال آزمایشی ثبت کنید، و بررسی کنید که ردیف جدید در Google Sheet ظاهر شده باشد.

---

**نکته:** اگر آدرس هنوز تنظیم نشده باشد، فرم داده را به‌صورت موقت در `localStorage` مرورگر ذخیره می‌کند تا داده‌ای از دست نرود — اما برای اشتراک‌گذاری با شرکت‌کنندگان واقعی، اتصال به Sheet ضروری است.

# راه‌اندازی ماژول ۲ — پانل ارزیابی دلفی

ماژول ۲ از همان Google Sheet و همان Web App ماژول ۱ استفاده می‌کند؛ نیازی به ساخت پروژه جداگانه نیست.

## ۱. به‌روزرسانی Apps Script
- در همان Google Sheet: Extensions → Apps Script
- کل محتوای فایل را پاک کرده و نسخه جدید `apps-script.gs` را جایگزین کنید (این نسخه هم ماژول ۱ و هم ماژول ۲ را پشتیبانی می‌کند)
- ذخیره کنید

## ۲. Deploy مجدد (نسخه جدید، همان URL)
- Deploy → Manage deployments
- روی آیکن مداد (ویرایش) کنار deployment فعلی بزنید
- در قسمت Version: گزینه **New version** را انتخاب کنید
- Deploy را بزنید
- آدرس Web App تغییر نمی‌کند — نیازی به تغییر `ENDPOINT_URL` در `signal-intake.html` نیست

## ۳. اتصال فرم ماژول ۲
فایل `delphi-elicitation.html` را باز کنید و همان آدرس Web App (دقیقاً همان آدرسی که در ماژول ۱ استفاده کردید) را در خط زیر جایگزین کنید:

```js
const ENDPOINT_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE";
```

## ۴. نحوه کار
- فایل به‌صورت خودکار سیگنال‌های ثبت‌شده در ماژول ۱ را می‌خواند
- در **دور اول**، هر خبره سه بعد (پذیرفتنی بودن، اهمیت، فوریت) را برای هر سیگنال امتیاز می‌دهد
- در **دور دوم**، میانه نظر گروه (بر پایه پاسخ‌های دور اول) به‌صورت ناشناس نمایش داده می‌شود تا خبره در صورت تمایل نظر خود را بازبینی کند
- پاسخ‌ها در برگه جدیدی به نام `DelphiResponses` در همان Sheet ذخیره می‌شوند

## محدودیت‌های نسخه فعلی (برای تکرارهای بعدی)
- فرم فعلی بررسی نمی‌کند که آیا یک خبره قبلاً در همین دور رأی داده یا نه؛ کنترل تکرار در همین Sheet قابل انجام است
- شناسه سیگنال بر اساس شماره ردیف در Sheet است — حذف دستی ردیف‌ها ممکن است شناسه‌ها را جابه‌جا کند

# راه‌اندازی ماژول ۳ — داشبورد پایش

ماژول ۳ هم از همان Sheet و همان Apps Script استفاده می‌کند.

## ۱. به‌روزرسانی Apps Script
- نسخه جدید `apps-script.gs` (که اکنون شامل هر سه ماژول است) را جایگزین کد قبلی در Extensions → Apps Script کنید
- Deploy → Manage deployments → پنسیل → Version: **New version** → Deploy
- آدرس Web App تغییر نمی‌کند

## ۲. اتصال داشبورد
در فایل `monitoring-dashboard.html`، همان آدرس Web App را جایگزین کنید:

```js
const ENDPOINT_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE";
```

## ۳. محتوای داشبورد
- **نقشه اولویت‌بندی:** نمودار حبابی سیگنال‌ها بر اساس اهمیت (محور افقی) و فوریت (محور عمودی)؛ اندازه حباب = تعداد پاسخ خبرگان. سیگنال‌هایی که در گوشه بالا-راست قرار می‌گیرند (اهمیت و فوریت بالا) بیشترین نیاز به توجه سیاست‌گذاری را دارند
- **وضعیت ارزیابی:** نسبت سیگنال‌های ارزیابی‌شده به کل
- **نمودارهای تفکیکی:** بر اساس حوزه زیست‌پزشکی، سطح بلوغ، و دامنه جغرافیایی
- **جدول کامل سیگنال‌ها:** با فیلتر بر اساس حوزه، بلوغ، و شدت

نقشه اولویت‌بندی همواره از **آخرین دور موجود** داده دلفی برای هر سیگنال استفاده می‌کند (دور دوم در صورت وجود، در غیر این صورت دور اول).

## محدودیت‌های نسخه فعلی
- داشبورد در هر بار بارگذاری صفحه، یک‌بار داده می‌خواند (نه به‌صورت زنده/real-time)؛ برای داده تازه، صفحه را رفرش کنید
- فیلترهای پایین صفحه فقط روی جدول اعمال می‌شوند، نه روی نمودارها — اگر لازم شد می‌توان در تکرار بعدی این هماهنگی را اضافه کرد

# راه‌اندازی ماژول ۴ — رصد خودکار ادبیات

ماژول ۴ یک اسکریپت پایتون است، نه صفحه وب. سیگنال‌های کاندید را از PubMed (پایگاه رسمی و مستند NIH/NLM، نه یک وب‌سایت اسکرپ‌شده) استخراج و به برگه جدیدی به نام `CandidateSignals` در همان Sheet ارسال می‌کند — نه مستقیماً به برگه `Signals` — تا همچنان یک نفر آن‌ها را بازبینی و تأیید کند.

## ۱. به‌روزرسانی Apps Script
- نسخه جدید `apps-script.gs` (شامل هر چهار ماژول) را جایگزین کد قبلی کنید
- Deploy → Manage deployments → پنسیل → Version: **New version** → Deploy

## ۲. نصب پیش‌نیاز پایتون
```bash
pip install requests --break-system-packages
```

## ۳. تنظیم آدرس
در ابتدای `literature_monitor.py`، همان آدرس Web App را جایگزین کنید:

```python
ENDPOINT_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE"
```

## ۴. اجرا
```bash
python3 literature_monitor.py
```

خروجی نمونه:
```
در حال جست‌وجو: هوش مصنوعی در پزشکی ...
  + Ethical governance of generative AI in clinical decision support
  = تکراری، رد شد: Algorithmic bias in diagnostic imaging models
پایان یافت. ۳ کاندید جدید، ۱ تکراری، ۰ خطا.
```

## ۵. اجرای زمان‌بندی‌شده (اختیاری)
برای اجرای روزانه خودکار، یک cron job اضافه کنید:
```bash
crontab -e
# هر روز ساعت ۸ صبح:
0 8 * * * cd /مسیر/پروژه && python3 literature_monitor.py >> monitor.log 2>&1
```

## نحوه کار
- برای هر حوزه زیست‌پزشکی (ژنومیک، عصب‌فناوری، پزشکی دقیق، فناوری‌های باروری، ارگانوئید، سلامت دیجیتال، هوش مصنوعی در پزشکی)، عبارت جست‌وجوی مرتبط با اخلاق/حاکمیت را در PubMed اجرا می‌کند
- مقالات ۱۴ روز اخیر را می‌آورد (قابل تنظیم در `LOOKBACK_DAYS`)
- هر مقاله به‌صورت یک سیگنال کاندید (عنوان، تاریخ انتشار، لینک PubMed) به `CandidateSignals` ارسال می‌شود
- سرور (Apps Script) بر اساس لینک منبع، از ثبت تکراری جلوگیری می‌کند — اجرای مکرر اسکریپت بی‌خطر است
- سرعت درخواست‌ها عمداً پایین نگه داشته شده تا با محدودیت نرخ رسمی PubMed (حدود ۳ درخواست در ثانیه بدون کلید API) سازگار باشد

## گام بعدی برای بازبینی
سیگنال‌های کاندید در `CandidateSignals` باید توسط یک عضو تیم بررسی شوند؛ موارد تأیید‌شده را می‌توان با کپی ردیف به برگه `Signals` یا با پر کردن مجدد فرم ماژول ۱ ارتقا داد.

## محدودیت‌های نسخه فعلی (برای تکرارهای بعدی)
- فقط PubMed پوشش داده شده است؛ پایگاه‌های پتنت و رصد رسانه به عمد در این نسخه گنجانده نشدند — اغلب سرویس‌های پتنت/رسانه یا نیاز به کلید API پولی دارند یا اسکرپ کردن مستقیم آن‌ها با شرایط استفاده (ToS) در تضاد است؛ افزودن آن‌ها در تکرار بعدی با یک API رسمی (مثل Lens.org یا NewsAPI) پیشنهاد می‌شود
- بازبینی و ارتقای کاندیدها به `Signals` هنوز دستی است

# راه‌اندازی ماژول ۴ — رصد خودکار ادبیات علمی

بر خلاف سه ماژول قبلی، این ماژول یک صفحه وب نیست — یک اسکریپت Node.js است که به‌صورت دوره‌ای اجرا می‌شود و سیگنال‌های جدید را مستقیماً در همان Sheet ثبت می‌کند. **هیچ تغییری در Apps Script لازم نیست** — این اسکریپت دقیقاً همان قالب داده‌ای ماژول ۱ را ارسال می‌کند.

## ۱. پیش‌نیاز
Node.js نسخه ۱۸ یا بالاتر (شما در حال حاضر v22.23.1 دارید — کافی است).

## ۲. تنظیم فایل
فایل `literature-monitor.js` را باز کنید و این دو خط را ویرایش کنید:

```js
const ENDPOINT_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE"; // همان آدرس ماژول‌های قبلی
const CONTACT_EMAIL = "PASTE_A_CONTACT_EMAIL_HERE"; // ایمیل شما — NCBI (پاب‌مد) برای ابزارهای خودکار این را توصیه می‌کند
```

## ۳. اجرای آزمایشی (بدون ثبت واقعی)
```bash
node literature-monitor.js --dry-run
```
این حالت فقط عناوین مقالات یافت‌شده را در ترمینال نمایش می‌دهد، چیزی در Sheet ثبت نمی‌شود.

## ۴. اجرای واقعی
```bash
node literature-monitor.js
```
مقالات جدید هر حوزه (ژنومیک، عصب‌فناوری، پزشکی دقیق، فناوری‌های باروری، ارگانوئید، سلامت دیجیتال، هوش مصنوعی در پزشکی) از PubMed جست‌وجو و به‌عنوان سیگنال جدید در برگه `Signals` ثبت می‌شوند.

اجراهای بعدی فقط مقالات **جدید** را ثبت می‌کنند (شناسه مقالات قبلی در فایل `seen-articles.json` کنار اسکریپت نگه‌داری می‌شود).

## ۵. اجرای دوره‌ای (اختیاری)
برای رصد مستمر (مطابق هدف فاز اول)، می‌توانید یک cron job اضافه کنید، مثلاً اجرای هفتگی هر دوشنبه ساعت ۹ صبح:

```bash
crontab -e
# خط زیر را اضافه کنید (مسیر را با مسیر واقعی فایل جایگزین کنید):
0 9 * * 1 cd /path/to/signal-intake && /usr/bin/node literature-monitor.js >> literature-monitor.log 2>&1
```

## نکته مهم: بررسی انسانی پیش از دلفی
سیگنال‌های ثبت‌شده توسط این اسکریپت، به‌طور خودکار مقادیر «سطح بلوغ»، «دامنه جغرافیایی» و «شدت اخلاقی اولیه» را به‌صورت `نیاز به بررسی` ثبت می‌کنند — چون این‌ها قضاوت‌هایی هستند که یک اسکریپت نمی‌تواند به‌جای شما انجام دهد. پیش از استفاده از این سیگنال‌ها در پانل دلفی (ماژول ۲)، این ردیف‌ها را در Sheet باز کرده و مقادیر واقعی را جایگزین کنید. برای پیدا کردن سریع آن‌ها، ستون `submitterName` را فیلتر کنید — سیگنال‌های خودکار با «ربات رصد ادبیات (PubMed)» مشخص شده‌اند.

## محدودیت‌های نسخه فعلی
- فقط PubMed پوشش داده شده است (ادبیات داوری‌شده)؛ پایگاه‌های پتنت، رسانه، و فراخوان‌های پژوهشی در فاز اول ذکر شده‌اند اما در این نسخه پیاده‌سازی نشده‌اند
- استخراج چکیده با یک الگوی ساده انجام می‌شود، نه یک XML parser کامل — در موارد نادر ممکن است چکیده به‌درستی استخراج نشود
- جست‌وجو به زبان انگلیسی است (پوشش استاندارد PubMed)؛ ادبیات فارسی‌زبان را پوشش نمی‌دهد
